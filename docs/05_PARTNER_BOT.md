# Partner Bot

## Назначение

`partner_bot` управляет полным жизненным циклом партнёра:

- регистрация,
- модерация,
- обработка заказов,
- управление профилем и реквизитами.

## Модель статусов партнёра

- `ожидает`
- `активный`
- `приостановлен`
- `отклонён`

Статус хранится в `ServiceDraft.status`.

## Регистрация (FSM)

Партнёр заполняет анкету в `ServiceDraft` по шагам:

- базовые данные сервиса,
- график,
- диагностика,
- опционально банковские реквизиты.

Для типа `complex` анкета требует обе ветки классификации:

- `Категория ремонта`,
- `Категории апгрейда`.

В pending-редактировании драфта доступны только операционные поля анкеты;
пункты `Орг.-правовая форма`, `Налогообложение`, `Банковские реквизиты`
из quick-edit intentionally исключены.

После отправки анкеты:

- создается/обновляется `Service`,
- анкета помечается как ожидающая модерации,
- админам отправляется уведомление.

## Модерация

Админ в `partner_bot.handlers.admin`:

- одобряет,
- отклоняет,
- приостанавливает,
- восстанавливает.

При одобрении данные из draft материализуются в финальный `Service` + `ServiceBankDetails`.

## Работа с заказами

Партнёр может:

- принять/отклонить заявку,
- перевести в работу и отправить смету,
- изменить цену с обязательной причиной,
- перевести в `ready_for_pickup`.

## Профиль и реквизиты

- Операционные поля (`name/address/phone/hours/...`) редактируются в профиле.
- Банковские поля редактируются отдельно.
- Изменения критичных полей переводят сервис в повторную модерацию.

## Уведомления

Настройки уведомлений хранятся в `ServiceOwnerSettings` и управляются через inline toggle.
